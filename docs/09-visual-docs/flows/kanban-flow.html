Kanban del Técnico — Flujo de trabajo

Cómo un técnico gestiona tickets en el sistema: ciclo visual ágil desde la cola compartida hasta la resolución documentada.

Versión: 1.0
Fecha: 2026-10-15
Autor: NexusDev / NexusTV
Decisiones Arquitectónicas: ADR-006 (Solución Obligatoria), ADR-009 (Sistema Gestor)

Tablero Kanban: 5 Columnas de Atención

El técnico visualiza únicamente los estados activos y pertinentes a su jornada de resolución. Cada columna define el estado de propiedad y el ciclo de vida del ticket:

Cola del grupo
Status 1 (Nuevo) Sin técnico asignado

Tickets recién ingresados al grupo técnico pendientes de que un resolutor tome posesión.

#101 · Acceso VPN Grupo: Soporte N1
Mis tickets
Status 1 ó 2 Asignado a mí

Tickets bajo responsabilidad del técnico en bandeja personal, listos para iniciar trabajo activo.

#98 · Configuración Outlook Técnico: tech1
En progreso
Status 2 ó 3 Assigned / Planned

Incidencias en diagnóstico, ejecución o planificación de intervención técnica inmediata.

#85 · Falla en Impresora En ejecución activa
Pendiente
Status 4 (Waiting) En espera externa

Atención pausada por espera de confirmación del usuario, repuestos de hardware o terceros.

#74 · Cambio de Disco Esperando proveedor
Resuelto
Status 5 (Solved) Solución documentada

Problema resuelto satisfactoriamente. Requiere registro mandatorio de la solución técnica aplicada.

#63 · Reseteo de Password Solución registrada
Flujo de Acciones y Transiciones entre Columnas
1. Asignarme
POST /api/tickets/{id}/claim
Cola → Mis tickets (autoasignación)
2. Empezar
PATCH /status { status: 3 }
Mis tickets → En progreso (inicio)
3. Pendiente
PATCH /status { status: 4 }
En progreso → Pendiente (pausa)
4. Resolver
POST solutions + PATCH { status: 5 }
En progreso → Resuelto (solución obligatoria)
🔄 Transición de retorno: Cuando se recibe la respuesta esperada, la acción "Retomar" (o drag & drop) envía PATCH /status { status: 3 } para devolver el ticket de Pendiente → En progreso.

Transiciones Permitidas

Transición Acción UI Endpoint / Mutation Regla de Validación
Cola del grupo → Mis tickets Botón "Asignarme" o Drag & Drop POST /api/tickets/{id}/claim El usuario debe pertenecer al grupo del ticket y el ticket debe estar sin técnico asignado (status = 1).
Mis tickets → En progreso Botón "Empezar" o Drag & Drop PATCH /api/tickets/{id}/status { status: 3 } Sin restricción adicional (permite inicio libre).
En progreso → Pendiente Botón "Pendiente" o Drag & Drop PATCH /api/tickets/{id}/status { status: 4 } Pausa de SLA en GLPI por espera externa.
Pendiente → En progreso Botón "Retomar" o Drag & Drop PATCH /api/tickets/{id}/status { status: 3 } Reactiva el trabajo sobre la incidencia.
En progreso → Resuelto Botón "Resolver" o Drag & Drop a columna POST /api/tickets/{id}/solutions
PATCH /api/tickets/{id}/status { status: 5 } 		SOLUCIÓN ESCRITA OBLIGATORIA (ADR-006)
Validada estrictamente en el backend. Arrastrar a Resuelto sin solución abre el modal de resolución.

Mapeo de Estados GLPI

Columna Kanban Estados GLPI Visibilidad
Cola del grupo 1 (New) sin assignee Siempre visible
Mis tickets 1, 2 (New / Assigned) asignados a mí Siempre visible
En progreso 2, 3 (Assigned / Planned) Siempre visible
Pendiente 4 (Pending) Siempre visible
Resuelto 5 (Solved) Siempre visible

* Nota: El estado Cerrado (6) de GLPI no aparece en el Kanban del técnico.

Operaciones Fuera del Kanban

Estado Cerrado (6) de GLPI:

Los tickets cerrados definitivamente no se muestran en el tablero Kanban para evitar sobrecarga cognitiva. Permanecen accesibles y consultables mediante la vista tabular completa en /tickets.

Reapertura de Tickets Resueltos:

La reapertura de un ticket con status = 5 (hacia En progreso o Nuevo) no se permite por drag & drop en el Kanban. Debe ejecutarse exclusivamente desde la vista de detalle del ticket (/tickets/{id}) con justificación.

Regla Estricta ADR-006: Solución Obligatoria

El paso a Resuelto exige una solución escrita. El sistema lo valida en el backend (no solo en la UI). Intentar arrastrar una tarjeta a la columna "Resuelto" sin solución registrada abre inmediatamente el modal de solución obligatoria, impidiendo la mutación sin el texto correspondiente.
